> 요청자: 프로젝트 오너 | 작성: Claude (AI-first architect 관점)
> 목적: SPRINT-002 이후 "스프린트 메모리 소실 / 문서화 붕괴 / 가짜 데이터" 문제의 근본 원인을 진단하고, 장기(수년, 10,000+ 파일) 유지보수가 가능한 구조를 제안한다.

## 총평

스프린트 프레임워크 자체는 있지만, 그 프레임워크를 지키도록 강제하는 장치가 하나도 없다. SPRINT-001은 사람이 8단계 문서를 성실히 다 채웠기 때문에 잘 굴러갔고, SPRINT-002는 아무도 강제하지 않으니 조용히 2개 문서(`01_PRD.md`, `02_BUILD.md`)로 축소됐다. 이건 습관 문제가 아니라 **문서화를 강제하는 구조가 없는 워크플로우 설계 문제**다.

## 1. 증거로 확인된 핵심 문제

### 1-1. SSOT(`ROADMAP.md`)가 비어있었다

`ROADMAP.md`는 CLAUDE.md에 "스프린트 종료 후 반드시 반영"하도록 명시된 프로젝트 전체의 단일 진실 공급원인데, 실제로는 Vision/북극성 지표/Sprint 히스토리/Backlog 전부가 `[작성]`, `[기능명]`, `[날짜]` 형태의 템플릿 플레이스홀더 그대로 남아 있었다 (SPRINT-001·002가 이미 진행됐음에도). Claude Code가 세션마다 참조할 "기억"이 애초에 존재하지 않았던 것 — 이것이 "이전 결정을 계속 잊어버린다"는 현상의 직접적 원인이다.
→ **조치**: 이 리뷰와 함께 `ROADMAP.md`를 SPRINT-001/002 실제 산출물 기반으로 채움 (같은 커밋).

### 1-2. SPRINT-002는 8단계 프레임워크를 스킵했다

SPRINT-001: `01_DISCOVER → 08_ITERATE` 8개 문서 + `user-research/personas.md` + `metrics.md` 완주.
SPRINT-002: `01_PRD.md`, `02_BUILD.md` 2개뿐. Discover/Define/Design/Validate/Iterate 산출물 없음. 프레임워크가 "선택 사항"이 되는 순간 바로 스킵된다는 것을 스스로 증명한 사례.

### 1-3. 역할 기반 에이전트가 실행 가능한 서브에이전트가 아니다

`.claude/agents/*.md` 5개 파일은 페르소나 설계는 상세하지만 Claude Code 서브에이전트 형식에 필요한 YAML frontmatter(`name`, `description`, `tools`)가 없다. 즉 Agent 도구로 실제 호출·위임이 불가능한, 사람이 수동으로 참조하는 문서일 뿐이다. 역할 분리·핸드오프·Definition of Done이 문서 안에서만 존재하고 실행에서는 강제되지 않는다.

### 1-4. AI 리서치 파이프라인에 출처·검수 개념이 없다

`scripts/mine-hustle.ts`: 유튜브 자막 → Claude API → 21개 필드 JSON 추출 → 구조 검증(필드 존재/enum/배열 길이)만 통과하면 즉시 `data/side-hustles.json`에 append. 문제:

- 숫자(월수익, trendScore 등)가 사실인지 검증하는 단계가 없다 — AI가 생성한 값이 그대로 프로덕션 데이터가 된다.
- `types/index.ts`의 `SideHustle`에 `sourceUrl`/`extractedAt`/`reviewStatus` 같은 출처·검수 필드가 전혀 없다. 한 번 merge되면 원본 영상 추적이 불가능하다.
- 사람 검수 게이트(PR, 스테이징, 승인) 없이 스크립트 성공 = 즉시 프로덕션 반영.
  → "가짜 데이터가 여기저기 섞여 있다"의 근본 원인은 스키마 자체가 신뢰도/출처를 표현할 수 없다는 것.

### 1-5. 데이터 저장 구조가 "지식 그래프" 비전과 불일치

`data/side-hustles.json`은 30개 항목의 flat 배열이고 `output: 'export'` SSG가 전체를 빌드 타임에 읽는다. 비전대로 부업마다 영상/코스/블로그/커뮤니티/관련 부업을 다대다로 연결하려면 지금 구조(단일 배열 + 문자열 태그 매칭)로는 불가능하다. 지금은 30개라 안 보이지만 자동 수집이 붙는 순간 반드시 무너진다.

### 1-6. SPRINT-001 Validate 결과의 신뢰도 자체도 재검토 필요

`07_VALIDATE.md`의 5개 세션이 전부 "성공"으로 끝나고 CTR 100%·체류 75.4초 같은 매우 깔끔한 수치인데, 실제 사용자 테스트였는지 AI가 정리를 매끄럽게 하다가 생성/윤색한 것인지 구분할 방법이 없다 (원시 인터뷰 노트 파일이 커밋되어 있지 않음). "가짜 데이터가 everywhere"라는 지적은 상품 데이터뿐 아니라 **검증 데이터에도** 적용해서 봐야 한다.

## 2. 디자인 시스템 — "AI가 만든 느낌"의 원인

- `tailwind.config.ts`의 색상(`primary #FF8FAB`, `accent #A8D8B9`)은 파스텔 SaaS 클론에서 흔한 조합. 형태(모양 언어, 타이포 위계, 아이콘 시스템)를 규정하는 토큰이 없고 색만 있다.
- 아이콘이 이모지(`icon: "🛒"`) — 플랫폼마다 렌더링이 달라 프리미엄 인상을 만들 수 없다.
- `tailwind.config.ts`에 `boxShadow.card` 토큰이 있는데 `HustleCard.tsx`는 이를 안 쓰고 `shadow-[0_2px_12px_rgb(0,0,0,0.04)]` 임의값을 직접 사용 — 토큰과 실제 사용이 이미 어긋나 있다.
- 타이포/스페이싱 스케일, 모션 시스템, 도메인 특화 시각화(난이도 게이지, 수익 막대 등)가 없다.

**제안**: CSS 변수로 토큰 확정 → Tailwind가 변수만 참조 → 컴포넌트 임의값 사용 금지(린트). 이모지를 커스텀 라인 아이콘 세트로 교체. 수익 출처 배지를 카드/상세 페이지에 노출해 "근거 있는 정보"라는 신호를 시각적으로 준다.

## 3. 권장 문서 3계층 분리

| 계층                     | 현재                                     | 개선                                                           |
| ------------------------ | ---------------------------------------- | -------------------------------------------------------------- |
| 영속 (거의 안 바뀜)      | `ROADMAP.md`가 빈 템플릿                 | `docs/knowledge/VISION.md`, `ARCHITECTURE.md`, `DATA_MODEL.md` |
| 결정 (append-only 누적)  | 스프린트 BUILD 로그에 산발적 기록        | `docs/adr/0001-*.md` 형태 ADR                                  |
| 휘발 (스프린트마다 갱신) | `CLAUDE.md` Current Sprint Status가 겸함 | 그대로 두되 세부 내용은 sprint 폴더로, `CLAUDE.md`는 링크만    |

`CLAUDE.md`가 "설정"과 "매번 덮어쓰는 상태 로그"를 겸하는 것이 문제 — Claude Code가 세션마다 자동으로 읽는 유일한 파일에 영속/휘발 정보가 섞이면, 휘발 정보가 바뀔 때마다 영속 정보의 신뢰도도 흔들린다.

## 4. 권장 레포 구조 (10,000+ 파일 대비)

```
/docs
  /knowledge/          # 영속 계층
  /adr/                # 결정 계층 (append-only)
  /sprints/SPRINT-NNN/ # 휘발 계층, 8단계 필수화
/data
  /hustles/{slug}.json  # flat 배열 → 항목당 1파일로 분리 (diff 국소화, 병렬 작업 안전)
  /resources/           # 영상/코스/블로그/커뮤니티 — hustleSlug로 참조하는 별도 엔티티
  /_inbox/               # AI 수집 결과, 미검수 상태
/scripts/research/      # 수집기, 소스별 분리 (youtube.ts, blog.ts, course.ts...)
```

## 5. 결론

### 가장 큰 아키텍처 실수 Top 3

1. `ROADMAP.md`가 비어있는 채로 방치됨 — 모든 컨텍스트 손실의 근본 원인.
2. 데이터 스키마에 출처(provenance) 개념이 없음 — AI 수집 데이터와 검증된 데이터를 구분 불가.
3. 워크플로우가 강제 장치 없이 선의에만 의존 — 에이전트가 실행 불가능하고, 스프린트 8단계가 선택사항.

### 지금 당장 할 최우선 개선 Top 3 (순서대로)

1. `ROADMAP.md` 실제 내용으로 채우기 — **이 리뷰와 함께 완료**.
2. `SideHustle` 타입에 `sourceUrl`/`reviewStatus` 필드 추가 + `mine-hustle.ts`를 inbox→승인 2단계로 전환.
3. `.claude/agents/*.md`에 frontmatter 추가해 실행 가능한 서브에이전트로 전환, 스프린트 생성을 스크립트로 강제.
